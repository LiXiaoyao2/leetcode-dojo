# 评测：提示到底有没有用

这个目录回答一个问题：**dojo 的 L1–L5 阶梯，比「直接问模型」和「先诊断再引导」好在哪里？**
所有数字由 `dojo eval` 生成，原始数据在 [raw.json](raw.json)，结果表在 [RESULTS.md](RESULTS.md)，
人工抽检表在 [REVIEW.md](REVIEW.md)。

## 测什么

同一道题、同一段「写到一半卡住」的代码、同一份真实失败输出，交给三种架构，按 L1→L5 逐档要提示：

| 架构 | 做法 |
| --- | --- |
| `ladder` | 现在 dojo 的协议：严格 L1–L5 纪律、每条只准推进一格、泄底/截断自动重问 |
| `naive` | 同样的输入和提问句，但没有阶梯纪律、没有重问——一次调用直接给 |
| `twopass` | 先让模型诊断卡点，再据诊断写提示（旧项目那套两次调用，去掉「必须问句结尾」和兜底） |

三条 arm 每档看到的上下文逐字相同，差别只在架构本身。

## 指标

客观（不依赖模型判断）：

| 指标 | 定义 |
| --- | --- |
| 泄底率 | L1–L4 出现可编译 Java 的比例（复用 dojo 自己的 `looksLikeJava`） |
| 重复率 | 与更早档位的字符 3-gram Jaccard ≥ 0.35 的比例 |
| 超长率 | 超过该档字数上限 20% 的比例（L1 120 / L2 150 / L3 220 / L4 350） |
| L5 跑绿 | 把第 5 档回复里的 Java 抠出来，丢进同一份官方样例测试，`mvn test` 全绿 |
| 中位时延 / tokens | 每档一次调用的墙钟时间与 token 数 |

主观：判官逐档打 1–5 分，并判 leak / repeats / actionable / tooLong。判官看不到 arm 名；
它自己偶尔会被推理占满预算，此时按预算阶梯重问，仍失败则退回规则判断并在结果里标 `heuristic`。

## 数据集

- `benchmark.txt`：一行一个 slug，20 道，覆盖数组 / 字符串 / 链表 / 树 / 图 / 回溯 / DP / 堆 / 设计题。
- `stuck/`：每题一段人工写的「卡住代码」。四种典型卡点：想法对但边界错、暴力能过样例但会 TLE、
  样例全绿但有隐藏 bug、结构没搭完。
- `cases/`：`dojo eval --snapshot` 生成的离线快照（题面 + 卡住代码 + 自动生成的官方样例测试）。
  跑评测不联网，只调模型。

## 怎么跑

```bash
bin/dojo eval --snapshot      # 只在改 benchmark 时需要，联网拉题
bin/dojo eval --cases 3       # 先跑 3 题试水
bin/dojo eval                 # 全量，写 RESULTS.md / REVIEW.md / raw.json
bin/dojo eval --no-judge      # 只跑客观指标，省一半调用
```

本轮全量：20 题 × 3 架构 × 5 档 ≈ 300 次提示调用 + 300 次判官调用 + 60 次 Maven，
四路并发约 20–30 分钟。

## 加一道题

1. 往 `benchmark.txt` 加 slug；
2. 在 `stuck/` 写一段真实的半成品代码（**不要**写完整解法，也不要写空模板）；
3. `bin/dojo eval --snapshot`；
4. 若生成的测试编不过，说明这题签名超出生成器能力——换题，或先 `--no-test` 手写测试。

## 本轮结果（2026-10-18，20 题 × 3 架构）

- **泄底**：三套都是 0%。受控提问本身就把「别给代码」压住了，这条线区分不出来。
- **L5 跑绿**：三套都是 20/20——20 道题对 L5 已经到天花板。
- **篇幅纪律**：超长率 阶梯 16% / 朴素 77% / 两次调用 68%。这是阶梯最实在的收益：
  它把「一开口就写小作文」按住了。
- **成本**：阶梯 6590 tokens/题、9.6 s；朴素 6432、9.0 s；两次调用 10380、16.3 s（比阶梯多 58% tokens、慢 70%）。
- **主观分**：4.29 / 4.27 / 4.15。差异小于判官自身的方差——用 `dojo eval --noise 5`
  把同一份答案评两次：5 份里 2 份出现分差，1 份差 2 分。所以 L5 那 0.7 分不能当结论。

诚实的结论：在「提问句已经把每档要求说清楚」的前提下，单次调用已经很强，阶梯赢在篇幅与
「不会越档」；两次调用既贵又慢。真正没测的是「用户随口一句『卡住了』」这种无约束提问——
那是下一个要补的 arm。

- 判官也是 LLM，和被测模型同源时可能偏爱同一种文风；主表同时给客观指标，主观分只作参考。
- 20 题、每档一次采样，只够看趋势，不够做显著性检验。
- 「卡住代码」只代表几类典型卡点，不代表所有卡点。
- L5 只验官方样例 + 自动生成的测试，不是完整判题；评测时统一补了 IDEA 模板本来就有的
  `import java.util.*` 和 `import kit.*`，所以「编译失败」不扣导入的账。
