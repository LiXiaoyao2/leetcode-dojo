## 怎么测的

- **数据集**：`eval/benchmark.txt` 里 20 道 leetcode.cn 题（简单 5 · 中等 15），覆盖数组、字符串、链表、树、图、回溯、动态规划、堆、设计题。每题不是空白模板，而是一段人写的「写到一半卡住」的代码，先真实跑一次自动生成的官方样例测试，把失败输出一起喂给模型。
- **三种架构**：`阶梯` 是现在 dojo 的 L1–L5 协议（单次调用 + 泄底/截断自动重问）；`朴素单次` 同样的输入、同样的「这一档要什么」，但没有阶梯纪律与重问；`诊断+引导` 先让模型诊断、再据诊断写提示（旧项目那套两次调用，去掉「必须问句结尾」和兜底）。
- **公平性**：三条 arm 每档看到的题面、卡住代码、失败输出、已给提示完全一致，提问句也逐字相同；差别只在架构本身。
- **客观指标**：泄底 = L1–L4 出现可编译 Java（复用 dojo 自己的检测器）；重复 = 与更早档位的字符 3-gram Jaccard ≥ 0.35；超长 = 超过该档字数上限 20%；L5 跑绿 = 把第 5 档回复里的 Java 抠出来丢进同一份官方样例测试，`mvn test` 全绿。
- **主观指标**：判官 `deepseek-v4.1-flash` 逐档打 1–5 分并判 leak / repeats / actionable / tooLong；判官看不到 arm 名字。另有 [eval/REVIEW.md](REVIEW.md) 供人工抽检校准。
- **成本**：整轮 54 分 45 秒，482043 tokens（含判官）。

## 样例：同一道题的 L1

`0001-two-sum 1. 两数之和`

**阶梯（现在）**

你的内层循环从 j = i 开始，示例 2 里 (2,4) 会先被 i=0、j=0 这一对拦住吗？再看示例 3 的两个 3，题目说「不能使用两次相同元素」，指的是下标不同即可，还是数值不能相同？

**朴素单次**

看两个边界：

1. 返回的两个下标**允许相等**吗？比如返回 `[0, 0]`，这算不算用了同一个元素两次？
2. 你内层循环的起点是 `j = i`。当 `j == i` 时，`nums[i] + nums[j]` 用到了数组里的几个元素？对照一下示例 3：`nums = [3,3], target = 6`，正确答案是 `[0,1]`，那它为什么不能是 `[0,0]`？

**诊断+引导**

两个边界先想清楚，再动手改：

1. 「不能使用两次相同的元素」约束的是**下标**还是**数值**？看示例 3：`[3,3]` 里两个 3 数值相同、下标不同，返回 `[0,1]` 算不算违规？那 `[0,0]` 呢——它是「两个元素」还是「同一个元素用了两次」？

2. 返回的下标有顺序要求吗？题干说「任意顺序返回答案」，但你本地用的是逐位比较的断言：如果真实答案是 `[0,1]` 而你返回 `[1,0]`，这个测试会判过还是判挂？

## 局限

- 判官也是 LLM，和被测模型同源时可能偏爱同一种文风；主表同时给客观指标，主观分只作参考。
- 20 道题、每档一次采样，样本量只够看趋势，不够做显著性检验。
- 「卡住代码」是人工写的，代表一类卡点，不代表所有卡点。
- L5 只验官方样例 + 自动生成的测试，不是完整判题。

## 复现

```bash
bin/dojo eval --snapshot        # 拉题（需要网络）
bin/dojo eval --judge            # 跑全量，写 eval/RESULTS.md
bin/dojo eval --cases 3          # 先跑 3 题试水
```
